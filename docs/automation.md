# プロジェクトのAutomation

ワークスペースの「Automation」からプロジェクトを選ぶと、閲覧できるタスクと履歴が表示されます。プロジェクト管理者は「レビュー担当者を設定」などのテンプレートを選び、トリガー、条件、変更するフィールドを指定できます。状態・担当者にはプロジェクトの候補またはイベントの値を使えます。

1. ルールIDを入力し、対象の状態・担当者を選びます。
2. 実在するサンプルタスクを選んで試運転します。状態・担当者の変更トリガーにはそのタスクの直近の更新イベントを、手動トリガーには現在値を使います。試運転はタスク、受付待ち、通知を増やしません。
3. 対象、変更前後、スキップ理由、実行主体を確認して「委任して公開」を選びます。公開後に発生したイベントが対象です。一時停止すると以前の委任も失効します。
4. タスクの履歴には人手・MCP・自動更新が、ルールの履歴には適用・スキップ・拒否や保留理由が表示されます。履歴のタスク名からそのタスクの履歴を開けます。操作を「維持」するか、公開時に許可した場合に「元に戻す」かを一度だけ選べます。別の人が編集したタスクは元に戻せません。

Draflowとの接続には両方の対応版が必要です。既存の8.2ルールは準備専用です。Studioで公開した定義は明示的に `apply: true` を指定します。Proodがタスク変更、派生イベント、操作の受領記録を一緒に保存します。復旧時の再配送でも同一の操作は一度だけ適用します。送信結果が確定しない場合はDraflowの運用コンソールで照合してください。管理者向けの導線はProodサーバーの `PROOD_DRAFLOW_OPERATOR_URL` で接続できます。

SQLiteとPostgreSQLは同じ移行9を使用します。ビルド後の `pnpm test:db:sqlite` と、テスト用 `DATABASE_URL` を指定した `pnpm test:db:postgres` で受領・再試行・補償・権限を検証できます。
